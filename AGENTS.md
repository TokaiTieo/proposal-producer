Read the installed SKILL.md. Upstream SOW creation is mandatory; sow_required selects customer delivery only. Default customer outputs remain proposal_docx and proposal_pdf.

Read the internal method module given by proposal-brief. business-case-and-proposal is included in this package and never resolved from an external skill library. Preserve upstream attribution and CC0-1.0 metadata. Keep actual input and output versions in production-chain.json; a handoff alone does not prove writing or business approval.

Use native Word headings, contents, numbering, captions, editable text and tables, correct metadata and actual export checks. Preserve scope, pricing and timing; label new terms as proposals until agreed. Existing independent business, legal, expression and technical checks apply, with no extra approval node. PPT extracts the actual written Proposal and preserves upstream files.

No external delivery, publication, paid services or implicit hook activation is authorized by installation. Synthetic tests and local trials are distinct from customer acceptance; preserve original failed outcomes and independent judgments.

Before authoring, apply references/client-content.md. Use client-2 itemized review schema: six separate editorial checks per actual artifact, individual signal dispositions and current hashes. Confirmed production narrative and excessive defense must be edited; a necessity analysis corrects false positives only. Every repeated condition needs a business purpose at each location. Release and the existing hook require no confirmed residuals and no pending signals; scanned text alone is not editorial approval. No extra user approval node is introduced.

For selected PPT, read references/ppt-image-render.md and the bundled SKILL.source.md; use the bundled scripts and presentation-image-prepare. Do not resolve an external ppt-image-render installation or silently use native templates. Follow current project style and existing authorization.
