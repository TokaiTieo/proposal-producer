# Agent installation entrypoint

This repository distributes proposal-producer 0.4.0-trial as a standalone Python installer containing the complete Skill ZIP and per-file hashes.

When the user requests installation, read README.md, clone this repository or download install.py, and run it with an available Python 3 runtime. The default is ~/.agents/skills/proposal-producer; --project or --dest selects another location. An identical repeat is unchanged; --update preserves the previous installation outside discovery directories.

After extraction, read SKILL.md. JSON contracts contain fields, thresholds, enums and checklists; schemas validate data; executable gates bind confirmation and review evidence to actual artifacts. Install requirements.txt in the task's Python environment if needed, then run the validate command. Do not silently change global packages or host permissions.

Report the actual installation path and version. Check document generation, PDF rendering and CJK fonts separately. Hook adapters require host registration; installation alone does not enable them. Installation does not request creation or external delivery of client proposals.

For proposal work, analyze relevant reference pages and fill presentation-plan.json. Render and internally calibrate key explanatory pages before production-check and full artifact registration. Reuse the existing content-confirmation node. The same independent checker records business and presentation judgments in quality-review.json. Report technical, argument and display outcomes separately. Real paired-artifact evaluation data is currently empty.

For v0.4, run doctor before authoring, configure task visual-profile and render-policy, and read references/visual-production.md. Native editing is the default; full-image delivery requires explicit selection. Preserve failed candidates. The renderer verifies actual object identities, image evidence and PDF exports; visual judgment is still required. Use requirements-test.txt for regression dependencies. Fixtures under evals/fixtures are never project defaults.
